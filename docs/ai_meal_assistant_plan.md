# خطة «المساعد الذكي لتوزيع الوجبات» — زنها Pro (اختياري، التحديث القادم)

طلب المالك (2026-11-28): مساعد بالذكاء الاصطناعي يعمل **بعد** إدخال بيانات العميل واختيار نظام الجدول (عادي، أو كارب سايكل، أو غيرهما من أنظمة النظام). مهمته **توزيع البدائل والوجبات** حسب تفضيلات العميل وتعليمات الأخصائي.
**لا يبدأ التنفيذ قبل اعتماد هذه الخطة.**

---

## 1) الفكرة في سطر
**الذكاء الاصطناعي يفهم ويخطط، والمحرك الحسابي في «زنها Pro» يحسب.**
- الذكاء الاصطناعي لا يحسب الجرامات ولا الحصص، لأن النماذج تخطئ في الحساب.
- الذكاء الاصطناعي يترجم كلام الأخصائي إلى **استراتيجية منظمة**: ما الأصناف المسموحة في كل وجبة؟ وكيف تتناوب على أيام الأسبوع؟ وما القيود؟
- المحرك الحالي يحوّل الاستراتيجية إلى حصص وجرامات تطابق السعرات والماكروز بدقة.
- النتيجة ذكية ومرنة، ومضمونة حسابياً.

---

## 2) شكل المساعد (الواجهة)
مكانه في المسار: **③ الوجبات**، زر «✦ المساعد الذكي (اختياري)». يظهر بعد اكتمال ① الاحتياج و② النظام والشكل، فيعرف السعرات ونوع النظام وأيام الكارب العالي والمنخفض.

### أ) لوحة الإعداد
```
┌──────────────────────────────────────────────────────────────┐
│ ✦ المساعد الذكي — توزيع الوجبات            [تجريبي]          │
│ النظام: كارب سايكل • 1850 سعرة (عالي) / 1550 (منخفض)         │
│                                                              │
│ اليوم الأساسي (كل الأيام)      [+ توزيع يوم مختلف]            │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ ☀ الفطور  • أساسية • 08:00                       ✎  ✕    │ │
│ │ «أريد أن تتنوع يومياً بين الجبن والبيض والزبادي والحليب   │ │
│ │  واللبن مع الخبز»                                         │ │
│ ├──────────────────────────────────────────────────────────┤ │
│ │ 🍎 سناك  • خفيفة • 11:00                                  │ │
│ │ (بلا وصف ← يختار المساعد من تفضيلات العميل)               │ │
│ ├──────────────────────────────────────────────────────────┤ │
│ │ [+ إضافة وجبة]                                            │ │
│ └──────────────────────────────────────────────────────────┘ │
│                                                              │
│ الاثنين والخميس: صيام  ✎  (توزيع مختلف: سحور + فطور)          │
│                                                              │
│ طريقة الكميات:  (•) مقاييس منزلية  ( ) جرام  ( ) مختلط        │
│ تعليمات عامة (اختياري): «عشاء خفيف، بلا مقليات»               │
│                                   [ ✦ ولّد بالمساعد ]         │
└──────────────────────────────────────────────────────────────┘
```

**عناصر اللوحة:**
- **«+ إضافة وجبة»:** نوعها (أساسية أو خفيفة)، واسمها (فطور، غداء، «قبل التمرين»…)، والموعد اختيارياً.
- **وصف الوجبة:** اختياري. يُكتب بلغة الأخصائي العادية، مع اقتراحات جاهزة بلمسة مثل «تنوع يومي» و«ثابتة كل يوم» و«بروتين عالٍ» و«بلا خبز».
- **«+ توزيع يوم مختلف»:**
  - يختار الأخصائي أياماً، مثلاً الاثنين والخميس، ويسمّيها، مثلاً «صيام».
  - يضع لها وجبات مختلفة، مثل سحور وفطور ووجبة ليل.
  - في الكارب سايكل يمكن ربطها تلقائياً بأيام الكارب العالي والمنخفض.
- **طريقة الكميات:** جرام، أو مقاييس منزلية (ملعقة، كوب، رغيف، حبة)، أو مختلط (جرامات للحوم والنشويات، ومقاييس للباقي)، كما في استبيان «زنها».

### ب) «فهمتُ منك» (قبل التوليد، شفافية)
بعد ضغط «ولّد» يعرض المساعد ما فهمه في سطور واضحة قابلة للتعديل قبل الحساب. مثال:
> **الفطور:** يدور على 5 أيام: جبن ← بيض ← زبادي ← حليب ← لبن، ومع كل يوم خبز. لا يجتمع حليب ولبن في وجبة واحدة. [تعديل]

يضغط الأخصائي «تابع» أو يصحح.

### ج) النتيجة
- **جدول الأسبوع:** الأيام × الوجبات، وفي كل خانة الأصناف بكمياتها، مثل «2 بيضة • رغيف بلدي ½ • خيار».
- **العدّاد اليومي:** المخطط مقابل الهدف لكل يوم، ✓ أو ⚠.
- **شارات لكل وجبة:** «✓ مطابقة لتعليماتك» أو «⚠ تعذّر: لا يوجد زبادي في تفضيلات العميل، استُبدل بلبن».
- **«لماذا؟»:** سطر شرح لكل وجبة من المخطِّط.
- **التعديل:** يدوياً لأي خانة (السحب بين الوجبات كما في 1.53)، أو «أعد توليد هذه الوجبة» أو «هذا اليوم» فقط.
- **«اعتمد الخطة»:** تصبح خطة عادية بنفس شكل الخطط الحالية، فيعمل معها كل شيء: الأرشيف، و④ المراجعة، والإرسال إلى «زنها»، وPDF، وقائمة المشتريات.

## 3) كيف يعمل من الداخل (التكامل بين النماذج)
```
تعليمات الأخصائي (عربي)  +  ملف العميل (مُجهّل: لا اسم ولا جوال)
        │
   ① المُحلِّل (يفهم العربية)  ── يحوّل الوصف إلى استراتيجية JSON بالإنجليزية،
        │                         مقيدة بأسماء أصناف قاعدتنا فقط (لا يخترع أصنافاً)
   ② المخطِّط (قوي في التفكير، قد لا يتقن العربية) ── يقرر التناوب على الأسبوع
        │                         والتنوع والاختيار الذكي عند الوصف المبهم + سطر «لماذا؟»
   ③ المحرك الحسابي (زنها Pro، بلا ذكاء اصطناعي) ── يحوّل الاستراتيجية إلى حصص بدائل
        │                         وجرامات/مقاييس منزلية تطابق السعرات والماكروز لكل يوم
   ④ المراجِع (قواعد ثابتة + فحص ذكي اختياري) ── يتحقق من القواعد والحساسية والتكرار؛
        │                         إن وجد خللاً يعيد للمخطِّط مرة أو مرتين بملاحظات محددة
   النتيجة للأخصائي
```

### لماذا نموذج وسيط؟ (كما طلبت)
- أقوى النماذج المجانية في التفكير والحساب، مثل gpt-oss وDeepSeek-R1، أداؤها بالإنجليزية أفضل من العربية.
- لذلك يقرأ **المُحلِّل** العربية بإتقان، ويكتب للمخطِّط **أمراً إنجليزياً منظماً** (JSON) فيه:
  - الأصناف بأسماء ثابتة، مثل `cheese_white` و`egg`.
  - الأدوار، مثل `protein` و`starch`.
  - القيود، مثل `not_together: [milk, laban]`.
- هكذا يعمل المخطِّط على مسألة إنجليزية واضحة، ولا يحتاج أن يفهم العربية.

### التشغيل
- يمر عبر **المحطة** (`hissati`) مثل موجّه الذكاء الاصطناعي الحالي (1.58).
- المفاتيح أسرار على الخادم، ولا تصل إلى المتصفح أبداً.
- عند انشغال نموذج أو بلوغه حد الاستعمال، ينتقل الطلب إلى النموذج التالي في السلسلة تلقائياً.
- النتائج المتكررة تُحفظ مؤقتاً، فلا يُكرر الطلب نفسه.

### الخصوصية
- لا يُرسل الاسم ولا الجوال ولا الملاحظات الحرة عن العميل.
- يُرسل فقط:
  - الاحتياج (السعرات والماكروز).
  - أسماء الأصناف المسموحة والممنوعة.
  - وصف الأخصائي للوجبات.
- الحساسية تُطبَّق في المحرك قبل الإرسال وبعده. الذكاء الاصطناعي لا يُستأمن عليها.

### تحديث 2026-11-28 (قرار المالك): Mistral بديلاً لـ Gemini
- **المُحلِّل:** Gemini Flash ← **Mistral (Medium أو Saba المتخصص في العربية)** 🇫🇷 ← GLM-Flash.
- **المخطِّط:** gpt-oss-120b (Groq) ← Qwen3 ← Kimi K2 Thinking (OpenRouter، اختياري لاحقاً) ← DeepSeek ← Llama (Cloudflare).
- **قبل الاعتماد:**
  - **الحدود:** حدود Mistral المجانية غير منشورة، وتُقرأ من لوحة الحساب (Limits).
  - **الصور:** دعم الصور في الخطة المجانية غير مؤكد. يُقاس بمعيار الصور الحالي (21 حالة من 1.58) قبل استعماله بديلاً في «مساعد الطعام».
  - **التدريب:** الخطة المجانية قد تشترط الموافقة على استعمال المدخلات في التدريب. نرسل بيانات مجهّلة فقط.
- **التنفيذ:** يبدأ بعد الطلب التالي للمالك. المفتاح يرسله المالك ويُحفظ سراً في المحطة فقط.

**تنبيهات من البحث:**
- الحدود المجانية تتغير كثيراً. مثلاً أنهت Cerebras تجربتها المجانية الدائمة، حسب بعض المصادر.
- لهذا يعتمد التصميم على **سلسلة بدائل** لا على مزود واحد.
- أراجع الحدود الرسمية قبل التنفيذ في صفحات Groq وAI Studio وOpenRouter.

**الاستهلاك التقديري:** كل توليد كامل يحتاج تقريباً 2–4 طلبات (تحليل، وتخطيط، ومراجعة واحدة).
- حصة Groq المجانية (1000 طلب يومياً) تكفي نحو **250–400 توليد يومياً**.
- عند التجاوز تنتقل السلسلة إلى البديل.
- **المفاتيح:** مفتاحا Gemini وGroq عندنا الآن. وأحتاج مفتاح **OpenRouter** إن اعتمدت DeepSeek بديلاً، وهو مجاني ومن دون بطاقة.

## 7) النتائج المتوقعة
- **الوقت:** توزيع أسبوع كامل بتعليمات الأخصائي في أقل من دقيقة، بدل 15–30 دقيقة يدوياً.
- **الدقة الحسابية:** السعرات والماكروز ضمن حدود الفحص الحالية (±5% للسعرات)، لأن الحساب للمحرك لا للذكاء الاصطناعي.
- **الالتزام بالتعليمات:** المستهدف 90% أو أكثر من الوجبات تطابق الوصف حرفياً، وما تعذّر يُشرح بشارة واضحة.
- **الأمان:** لا صنف من حساسية العميل، ولا صنف خارج القاعدة، ولا كمية غير عملية.
- **الاستمرارية:** إذا توقف كل مزودي الذكاء الاصطناعي يبقى ذ0 وذ2 يعملان، أي توزيع حسابي مباشر من الوصف المنظم.

## 8) قرارات مطلوبة منك
1. **اعتماد الفكرة الأساسية:** الذكاء الاصطناعي يفهم ويخطط، والمحرك يحسب.
2. **القواعد:** اعتماد البند 5، خاصة 8 (الصيام) و9 (الكارب سايكل) لأنهما سريريان، أو تعديلها.
3. **الخصوصية:** الموافقة على إرسال البيانات **المجهّلة** فقط (الاحتياج والأصناف والوصف) إلى مزودي الذكاء الاصطناعي.
