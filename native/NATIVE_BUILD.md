# بناء تطبيق «حصة» لأندرويد وآيفون (Capacitor)

## ما الجاهز وما لم يُجرَّب
- **جاهز ومختبر (بمحاكاة Capacitor في المتصفح، لا على جهاز):** حفظ الملفات ومشاركتها (Word/HTML/نسخة احتياطية)، معرّف الجهاز الأصلي لتفعيل المستخدم، بطاقة «تطبيق الجوال» (روابط التحميل والتحديث)، ضغط Word (1 ميغابايت ← ~30 كيلوبايت)، مناطق الأمان (نتوء الآيفون).
- **لم يُجرَّب على جهاز أو محاكي حقيقي:** كل البناء الأصلي (APK/IPA). نُفّذت الأوامر أدناه نظرياً فقط، فنفّذها وأبلغ بأي اختلاف. (بيئة التطوير التي بنت المشروع بلا Android SDK ولا Xcode ولا إنترنت.)
- **أسماء الحزم والإعدادات** كتبتها من المعرفة دون تحقق من npm؛ شغّل `npm run doctor` وراجع توثيق Capacitor الحالي.

## 0) المتطلبات
| | أندرويد | آيفون |
|---|---|---|
| النظام | Windows / macOS / Linux | **macOS فقط** |
| الأدوات | Node LTS، JDK 17، Android Studio (SDK + Build-Tools) | Node LTS، Xcode (الأحدث)، CocoaPods أو SPM |
| الحسابات | Google Play Console (رسم لمرة واحدة) للمتجر فقط | **Apple Developer Program (اشتراك سنوي)** لأي توزيع خارج جهازك |

## 1) التهيئة (مرة واحدة)
```bash
cd native
npm run setup                          # يثبّت Capacitor والإضافات (أحدث إصدار)
npm run web -- ../hissa_users.html     # ملف المستخدمين المُصدَّر من admin.html (يُرفض admin.html والقالب غير المربوط)
npm run add:android
npm run add:ios                        # على Mac فقط
npm run assets                         # يولّد الأيقونات وشاشات البداية من native/assets/
npm run sync
npm run doctor
```
> غيّر `appId` في `capacitor.config.json` (الافتراضي `app.hissa.dtahmed`) **قبل** `add:ios`/`add:android`؛ تغييره لاحقاً يتطلب إعادة إنشاء المنصتين.
> أيقونة المصدر 473 بكسل مكبَّرة؛ ضع أيقونة نهائية عالية الدقة (1024×1024) في `native/assets/icon-only.png` قبل النشر.

## 2) أندرويد
```bash
npm run android:open                   # Android Studio ← Run على محاكي/جهاز
npm run android:debug                  # APK تجريبي: android/app/build/outputs/apk/debug/app-debug.apk
```
**مفتاح التوقيع (مرة واحدة — احتفظ به ولا ترفعه إلى git؛ فقدانه يمنع تحديث التطبيق):**
```bash
keytool -genkeypair -v -keystore hissa-release.keystore -alias hissa -keyalg RSA -keysize 2048 -validity 10000
```
أضف في `~/.gradle/gradle.properties` (خارج المشروع): `HISSA_STORE_FILE=/path/hissa-release.keystore` و`HISSA_STORE_PASSWORD=…` و`HISSA_KEY_ALIAS=hissa` و`HISSA_KEY_PASSWORD=…`، وفي `android/app/build.gradle`:
```gradle
android { signingConfigs { release { storeFile file(HISSA_STORE_FILE); storePassword HISSA_STORE_PASSWORD; keyAlias HISSA_KEY_ALIAS; keyPassword HISSA_KEY_PASSWORD } }
          buildTypes { release { signingConfig signingConfigs.release; minifyEnabled false } } }
```
```bash
npm run android:release                # APK موقّع للتنزيل المباشر
npm run android:aab                    # AAB لمتجر Google Play
apksigner verify --print-certs android/app/build/outputs/apk/release/app-release.apk
```
**رابط التنزيل المباشر:** ارفع الـAPK على استضافة `https`، ثم في `admin.html` ← «⚙ إعدادات النظام ← 📲 تطبيق الجوال» الصق الرابط والإصدار (مثل 1.0.0) وأعد «تصدير نسخة المستخدمين». يرى المستخدم البطاقة في صفحته الرئيسية، وإشعار «تحديث متاح» إن كان إصداره أقدم. عند التثبيت يسمح المستخدم بـ«تثبيت تطبيقات من مصادر غير معروفة» لهذا المتصفح.

## 3) آيفون (على Mac)
```bash
npm run ios:open                       # Xcode
```
في Xcode: Signing & Capabilities ← Team، وBundle Identifier. ثم **Product ← Archive ← Distribute App** إلى App Store Connect (TestFlight أو المتجر) أو Ad Hoc.
- **لا يوجد «رابط تنزيل مباشر» لآيفون:** الخيارات رابط TestFlight أو App Store، أو Ad Hoc (حتى 100 جهاز مسجّل). ضع الرابط في بطاقة التطبيق. والبديل بلا حساب مطوّر: **التثبيت من المتصفح (PWA)** ← Safari ← مشاركة ← «إضافة إلى الشاشة الرئيسية».
- `Info.plist`: راجع مفتاح `ITSAppUsesNonExemptEncryption` وأسئلة تصدير التشفير في App Store Connect (التطبيق يستخدم AES-GCM وECDSA القياسيين).

## 4) ملاحظات تقنية في الجهاز (تحقّق منها)
- **المنشأ:** أندرويد `https://localhost` وآيفون `capacitor://localhost`: ثابت لـ IndexedDB. إن ظهرت شاشة «تعذّر التشغيل» على آيفون فالسبب غالباً عدم توفر WebCrypto في ذلك السياق، وهذا أهم فحص أول.
- **التصدير:** `window.print` وروابط التنزيل لا تعمل في WebView؛ عُوِّضت بحفظ الملف في CACHE ثم ورقة المشاركة (واتساب، بريد، «حفظ في الملفات»). **PDF:** «تصدير PDF» داخل التطبيق يشارك ملف HTML للعميل فيفتحه المستخدم في المتصفح ويطبع ← PDF؛ لتوليد PDF مباشر أضف إضافة طباعة أصلية (غير مُنفَّذة).
- **الفيديو المتحرك:** يحتاج `muted` و`playsinline` (موجودان). يقلّل من حركة النظام إن فُعِّل «تقليل الحركة».
- **رفع الملفات (xlsx للأغذية، الشعار، استرجاع النسخة):** `<input type=file>` يعمل في Capacitor ويفتح منتقي الملفات الأصلي.
- **التخزين:** بيانات المستخدم مشفّرة AES-GCM داخل IndexedDB في الـWebView. التطبيق يطلب `navigator.storage.persist()`. أخذ نسخة احتياطية دورية يبقى ضرورياً (حذف التطبيق يحذف البيانات).

## 5) قائمة التحقق على الجهاز (نفّذها يدوياً على أندرويد وآيفون)
1. إقلاع التطبيق: شاشة البداية ثم شاشة التفعيل بالفيديو المتحرك. 2. رمز الجهاز يبدأ بالحرف N ويبقى ثابتاً بعد إغلاق التطبيق وفتحه. 3. التفعيل بكود المدير والدخول. 4. إنشاء عميل حصص وعميل رياضي وتوليد الخطة. 5. تصدير Word ← تظهر ورقة المشاركة ← واتساب/بريد/حفظ في الملفات، ويفتح الملف في Word. 6. تصدير HTML. 7. «تصدير PDF» ← ملف HTML ← طباعة PDF من المتصفح. 8. نسخة احتياطية ثم استرجاعها. 9. رفع ملف الأغذية xlsx (للمدير) ومنتقي الملفات. 10. رفع الشعار. 11. تدوير الشاشة. 12. لوحة المفاتيح لا تغطي الحقول (جرامات، بحث). 13. منتقي الأصناف يظهر كاملاً. 14. نتوء الآيفون وشريط الصفحة الرئيسية لا يقصّان الواجهة (رأس وأسفل). 15. الإقلاع بلا إنترنت. 16. إنهاء التطبيق من المهام ثم فتحه: البيانات والتفعيل باقيان. 17. مسح بيانات التطبيق (أندرويد) ← رمز الجهاز نفسه. 18. إعادة تثبيت (آيفون) ← قد يتغير الرمز ويحتاج المدير لتحرير الخانة. 19. بطاقة التطبيق: فتح الرابط، المشاركة، النسخ، إشعار التحديث. 20. القفل التلقائي بعد 30 دقيقة.

## 6) الأمان: ما تغيّر وما لم يتغيّر
- **تغيّر:** داخل التطبيق يُربط التفعيل بمعرّف الجهاز الأصلي (أندرويد ANDROID_ID، آيفون identifierForVendor) مُجزَّأً بـ SHA-256، فيبقى ثابتاً عند مسح بيانات التطبيق في أندرويد. على آيفون يتغير عند حذف كل تطبيقات الناشر، فيستهلك إعادة التثبيت خانة جهاز يحرّرها المدير.
- **لم يتغيّر:** التحقق داخل التطبيق؛ APK معدَّل أو جهاز rooted/jailbroken يتجاوزه. الإيقاف الفوري والمزامنة بين الأجهزة يتطلبان خادماً (ويُضاف معه Play Integrity وApp Attest). مفتاح تشفير البيانات يُشتق من كلمة السر عند كل دخول ولا يُخزَّن؛ **الفتح بالبصمة مؤجَّل** (يتطلب مفتاحاً قابلاً للتصدير يُحفظ في Keychain/Keystore، وهذا قرار أمني منفصل).
- **قرار:** أُبقي التشفير AES-GCM في IndexedDB ولم ننتقل إلى SQLCipher: البيانات مشفّرة أصلاً، والانتقال إعادة كتابة كبيرة بمكسب أمني ضعيف ما دام المفتاح مشتقاً من كلمة السر.

## 7) المتاجر
- **Google Play:** حساب مطوّر، AAB موقّع، سياسة خصوصية، نموذج «سلامة البيانات» (بيانات صحية تُخزَّن على الجهاز فقط)، مستوى API المستهدف الذي يتطلبه المتجر حالياً (يتولاه Capacitor عادةً).
- **App Store:** سياسة خصوصية، وصف دقيق (أداة للأخصائيين وليست جهازاً طبياً ولا تشخّص)، ومراجعة 4.2 (الحد الأدنى للوظائف): التطبيق يعمل بلا إنترنت بمنطق كامل وليس مجرد موقع، لكن قد تُرفض الأغلفة المبسّطة، فجهّز شرحاً للمراجع.
